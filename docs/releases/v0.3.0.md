# PostVibeClarity v0.3.0 — Launch operations

## Repository operations coverage

v0.3.0 adds six deterministic Level 0 checks to the `launch-operations` skill. Each check inspects bounded repository evidence with `filesystem-read` access only:

- `launch-operations.release-process`
- `launch-operations.rollback-process`
- `launch-operations.monitoring-response`
- `launch-operations.health-check`
- `launch-operations.backup-restore`
- `launch-operations.maintenance-ownership`

Adaptive applicability uses the discovered project shape and capabilities. Release, recovery, monitoring, health, backup, and ownership profiles adapt for web, backend, worker, mobile, desktop, CLI, library, mixed, and ambiguous projects. Health evidence is conditional on a network service, backup evidence is conditional on persistent data, and uncertainty remains `unverified` rather than being converted into a pass.

Usable documentation is content-checked against versioned profiles; a filename alone is insufficient. Missing or vague repository evidence is `unverified`. A repository pass says only that the visible written or configuration evidence met the profile.

The checks do not inspect live providers, deployment state, alert delivery, health endpoint responses, backup creation, restore results, or rollback execution.

## Guided written remedies

After an audit, `launch-operations` can guide one written remedy at a time. It asks one plain-language question at a time, accepts unknown answers, previews the exact target and unresolved decisions, and requires separate Level 2 approval before writing. Generated drafts preserve unknown decisions as visible `Unresolved decision:` entries.

An approved remedy writes only the exact Markdown runbook or bounded Markdown update that was previewed. A repository audit or broad readiness request authorizes no source, configuration, workflow, infrastructure, external-service, staging, commit, release, provider, or production change. A fresh repository check is required after an approved document edit.

## Installation and upgrade

The v0.3.0 package contains six project-scoped skills:

- `post-vibe-clarity`
- `project-discovery`
- `secret-exposure`
- `launch-essentials`
- `launch-operations`
- `universal-verification`

For a new installation or upgrade to `v0.3.0`, use the pinned guide for the current host. Each guide stages all six skills from the release tag, records the resolved commit, compares existing directories, preserves a bounded backup, and verifies discovery before locally changed content is reapplied:

- [Agent Skills hosts](../installation/agent-skills.md)
- [Codex](../installation/codex.md)
- [Claude Code](../installation/claude-code.md)
- [Cursor](../installation/cursor.md)
- [Windsurf](../installation/windsurf.md)

Do not upgrade from a moving default branch.

## Before-and-after evidence

The [before-and-after launch candidate](../../examples/launch-candidate/README.md) demonstrates repository evidence changing from missing operations guidance to six content-complete example runbooks. The renderer-backed [sample report](../examples/sample-report.md) is generated from the real `before` fixture and retains the operations findings, command evidence, coverage gaps, and repository-only boundary.

Neither example executes or verifies a live deployment, alert, health endpoint, backup, restore, rollback, provider, or production environment.

## Remaining limits

Live and provider operations verification remains open roadmap work. Active environment verification, recovery exercises, performance and cost checks, provider adapters, application-code or configuration remedies, deep shape packs, legal-sufficiency workflows, strong containment, and cross-agent runtime acceptance are not included in this release.

This report reduces uncertainty by recording checks and evidence. It does not certify that the application is production ready, secure, compliant, or free of defects.
