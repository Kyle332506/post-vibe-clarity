# Security policy

## Supported versions

The current `0.1.x` release line is supported for security reports. Earlier versions may not receive fixes; include the exact version you tested so maintainers can assess the report.

## Report a vulnerability

Please report a vulnerability privately through this repository's Security tab and its private vulnerability-reporting flow. Do not open a public GitHub issue for a suspected vulnerability. Private reporting gives maintainers space to assess impact and coordinate a response before details are disclosed.

Do not include secrets in a report. Remove or redact credentials, tokens, private keys, personal data, and any private project material. If a secret was exposed, revoke or rotate it through the relevant service rather than sending it to the maintainers.

Include, where available:

- Affected versions and environments.
- The security impact and the conditions required to trigger it.
- Safe reproduction steps or a minimal sanitized example.
- A suggested mitigation or workaround, if you have one.

## Response boundaries

Maintainers will assess reports in good faith, but this project makes no fixed response SLA. A report, investigation, or fix does not guarantee that other issues are absent. PostVibeClarity provides evidence and next actions; it does not certify that a project is production-ready, secure, compliant, or defect-free.

For non-security defects, use the Bug report form described in [SUPPORT.md](SUPPORT.md). For general contribution workflow, see [CONTRIBUTING.md](CONTRIBUTING.md).
